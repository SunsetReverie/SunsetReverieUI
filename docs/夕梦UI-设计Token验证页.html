设计 Token 验证页

把《夕梦 UI 组件库开发规划》第四章的 Token 约定渲染成看得见的东西：色板阶数、字号节奏、间距体系、 圆角与阴影的 flat / glass 双套值。用于 W1 评审对齐视觉方向。

data-sr-theme=light data-sr-style=flat 点击任意色块可复制变量名

00Token 分层模型

三层单向依赖，禁止跨层引用。组件只消费 L2 或自建 L3，不得直接引用 L1 色板。

L1
原始层 Primitive
--sr-sunset-500 · --sr-night-950 · --sr-space-4
↓ 语义映射（随主题 / 风格变化）
L2
语义层 Semantic
--sr-color-primary → var(--sr-sunset-500)
↓ 组件内再映射
L3
组件层 Component
--sr-button-bg → var(--sr-color-primary)
本页所有 UI 元素（侧栏、卡片、分割线、表格）都只用 var(--sr-*) 声明，没有写死颜色与圆角。 因此它同时验证了一件事：这套 Token 足以独立支撑一个完整页面。

01原始色板（L1）

8 个色系 × 11 阶。色块内数字为该色与黑/白文字的最高 WCAG 对比度，可作可读性参考。

暗色下主色提亮一阶：--sr-color-primary 在 light 指向 sunset-500， 在 dark 指向 sunset-400。这是暗色主题最容易被忽略的一处，切换右上角主题即可看到差异。

02语义色映射（L2）

显示当前主题下 CSS 变量解析后的实际色值。切换明暗后本区块实时变化，而上方色板保持不变——这正是 L1 / L2 的分工。

03字号阶梯

8 档字号与配套行高。右侧为真实渲染效果，用于判断层级对比是否足够。

04间距节奏

4px 基数。变量名直接使用数值（--sr-space-4 = 16px），避免「space-3 到底是 8 还是 12」的记忆成本。

05圆角

当前风格 flat —— 切换侧栏的「质感」可对比 flat 与 glass 两套值。
注意 --sr-radius-base 是可变 Token：flat 6px、glass 12px，因此组件必须写 var(--sr-radius-base) 而不是硬编码 6px。

06阴影层级

当前风格 flat —— flat 用紧凑硬边表达层次，glass 用高扩散低透明度制造悬浮。

暗色阴影需补偿：文档 4.6 只给了亮色阴影值，暗底上 rgba(16,20,26,.06) 几乎不可见。 本页在暗色下改用黑色并提高不透明度（rgba(0,0,0,.5~.8)），此项需回填到 tokens.css 与规划文档。

07质感对照

同一个「容器表面」在两种风格下的差异：圆角、阴影、模糊、边框高光。左侧始终是 flat，右侧始终是 glass，不随开关变化。

data-sr-style="flat"
扁平表面
不透明背景 · 6px 圆角 · 紧凑阴影 · 无模糊
data-sr-style="glass"
毛玻璃表面
半透明背景 · 12px 圆角 · 高扩散阴影 · blur(16px)
右侧玻璃盒真实使用了 backdrop-filter，能透过它看到背后的顶部光晕。 这也说明毛玻璃的前提是背后必须有内容或颜色，否则模糊出来是一片灰。

08升级路径

本页是手写静态版，仅用于 W1 评审。它与 tokens.ts 之间还没有约束关系，因此数值可能漂移。

阶段形态数据来源风险
现在 静态单文件（本页） 手写，与文档第四章对齐 Token 调整后需人工同步
W2 生成式 Token Gallery internal/tokens 编译产物 需补一条生成脚本
W7+ 文档站 design/token.md 同上，作为 VitePress 页面 —
红线：页面里的值不能成为第二份真相。 W2 升级时必须改成从 tokens.ts 读取并注入模板，禁止继续手写十六进制值； 否则 token 一改，这一页就变成过期的假文档。
