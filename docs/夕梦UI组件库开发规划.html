01项目目标与边界

先把「做什么」和「坚决不做什么」钉死，避免范围蔓延。

1.1 定位

SunsetReverie-UI 服务于团队内的中后台系统、官网与内容站点。不面向开源社区，不发布到 NPM 公共 registry，只托管在私有 Git 仓库，下游通过 Git 依赖安装。

关键词含义具体约束
内部只服务自己人与少数项目不承诺公开 API 稳定性周期，但内部项目必须可控升级
黄昏美学视觉围绕日落、晚霞、余晖、薄暮暖橙 → 霞紫 → 暮蓝主色系，支持毛玻璃质感
双端一致Vite 与 Nuxt 4 行为一致浏览器侧逻辑必须 SSR 安全，零水合告警

1.2 目标

  1. 一套组件、两处渲染：Vue 3（Vite）与 Nuxt 4（SSR/SSG）渲染结果一致，控制台零 hydration mismatch。
  2. 完整设计系统：Token 三层、断点栅格、动效体系全部自研，Less 为唯一样式语言。
  3. 四维可切换：亮/暗、主题色、毛玻璃/扁平、响应式，全部由根属性 + CSS 变量驱动。
  4. 按需 + 全量双轨：支持 unplugin-vue-components 自动按需，也支持全量注册且产物可 tree-shake。
  5. 可维护的发布链路：Git tag 即版本，可精准锁定与回滚，变更可追溯。
  6. 示例即测试：文档示例、两个 playground 共享同一份源码。

1.3 非目标

非目标原因 / 替代方案
不发布 NPM 公共仓库内部使用，git 依赖已足够；未来需要再补 publish 流程
不做 Tailwind / UnoCSS / CSS-in-JS已定 Less；原子类由自研工具类生成
不自建图标库、不画 SVG全量依赖 Iconify 生态（见第八章）
不做低代码 / 可视化搭建 / 页面模板只提供原子与分子级组件
不做移动端原生 / 小程序适配仅 Web，响应式覆盖移动浏览器
不做 i18n 文案内置文案由 props 注入，语言包归业务侧
不兼容 IE / 旧 Edge基线见 1.4；允许 CSS 变量、color-mix
不做 Figma Token 自动同步一期手工维护，标为 P3 远期

2.3 BEM 落地细则

less
.sr-button {                       // Block
  display: inline-flex;
  height: var(--sr-button-height-md);
  border-radius: var(--sr-radius-base);
  background: var(--sr-button-bg);
  transition: background-color var(--sr-motion-duration-fast) var(--sr-motion-easing-standard);

  &__icon {                       // Element
    margin-inline-end: var(--sr-space-2);
    font-size: 1em;
  }

  &--primary {                    // Modifier：variant
    --sr-button-bg: var(--sr-color-primary);
  }

  &--lg {                         // Modifier：size
    height: var(--sr-button-height-lg);
  }

  &.is-loading,                   // State：此刻怎样
  &.is-disabled {
    cursor: not-allowed;
    opacity: .6;
  }
}
Modifier 表达「是什么」，State 表达「此刻怎样」。 --primary 是变体，is-loading 是状态，两者不可混用同一前缀，否则样式优先级与语义都会失控。

04设计系统与 Token 规范

三层 Token + 唯一数值源；Less 负责编译期结构，CSS 变量负责运行期皮肤。

4.1 三层模型

L1 原始层  --sr-red-500 / --sr-space-4
↓ 语义映射（随主题 / 风格变化）
L2 语义层  --sr-color-primary / --sr-shadow-md
↓ 组件内再映射
L3 组件层  --sr-button-bg / --sr-button-height-md
禁止跨层引用：组件级不得直接引用原始色板
  • 只改品牌色 → 覆盖 L2 的 --sr-color-primary，全站生效。
  • 改暗色模式 → 只重定义 L2，组件样式零改动。
  • 单点覆写 → 覆写 L2 或 L3 某个变量，不需要 !important 打架。

4.9 Token 视觉验证页（Token Gallery）

  • 系统主题监听用 matchMedia('(prefers-color-scheme: dark)') 的 change 事件，仅在 auto 模式生效。
  • 跨标签页同步用 window.addEventListener('storage')。
  • 写 DOM 的地方唯一：data-sr-theme / data-sr-style / root.style.colorScheme。

5.4 SSR 防闪烁（FOUC）

问题：SSR 输出的 <html> 无 data-sr-theme，浏览器先按浅色绘制，JS 读到 localStorage 才切暗色，用户看到一帧白闪。

方案：在 <head> 最靠前插一段阻塞式同步脚本，首次绘制前决定属性值。

html · index.html
<head>
  <meta charset="UTF-8" />
  <!-- 必须在所有 CSS/JS 之前，且不能加 defer/async -->
  <script>
    (function () {
      try {
        var d = document.documentElement
        var m = localStorage.getItem('sr-theme') || 'auto'
        var s = localStorage.getItem('sr-style') || 'flat'
        var dark = m === 'dark' || (m === 'auto' &&
          window.matchMedia('(prefers-color-scheme: dark)').matches)
        d.setAttribute('data-sr-theme', dark ? 'dark' : 'light')
        d.setAttribute('data-sr-style', s === 'glass' ? 'glass' : 'flat')
        d.style.colorScheme = dark ? 'dark' : 'light'
      } catch (e) {
        document.documentElement.setAttribute('data-sr-theme', 'light')
      }
    })()
  </script>
</head>

Nuxt 4 下由 Module 自动注入，用户无需手写（useHead({ script: [{ key: 'sr-theme-init', innerHTML: THEME_INIT_CODE, tagPriority: 'critical' }] })）。

最终组合策略

阶段做什么

6.6 useSrBreakpoint 与 SSR

typescript
/**
 * 响应式断点状态
 * SSR 安全：服务端返回指定初值（默认 md），客户端挂载后校正
 * @param options.ssrWidth 服务端推断的视口宽度
 */
export function useSrBreakpoint(options: { ssrWidth?: number } = {}) {
  const width = ref(options.ssrWidth ?? SR_BREAKPOINTS.md)

  const current = computed<SrBreakpoint>(() => {
    let hit: SrBreakpoint = 'xs'
    for (const bp of ORDER) if (width.value >= SR_BREAKPOINTS[bp]) hit = bp
    return hit
  })

  // 用 matchMedia 而非 resize 监听：性能更好，不阻塞主线程
  if (typeof window !== 'undefined') {
    const queries = ORDER.filter(b => b !== 'xs').map(bp => ({
      bp, mql: window.matchMedia(`(min-width: ${SR_BREAKPOINTS[bp]}px)`),
    }))
    const recompute = () => { /* 取所有满足的 mql 中最大断点下界 */ }
    recompute()
    for (const { mql } of queries) mql.addEventListener('change', recompute)
    onScopeDispose(() => {
      for (const { mql } of queries) mql.removeEventListener('change', recompute)
    })
  }

  return { width, current, isMobile, isTablet, isDesktop, isUp, isDown }
}

07动画系统详细设计

统一时长与缓动 Token；只动 transform 与 opacity；reduced-motion 是硬要求而非可选项。

7.1 五条设计原则

  1. 快而轻：交互反馈 ≤ 240ms，超过 300ms 会感到迟钝。
  2. 只动 transform / opacity：可走合成层。颜色过渡可接受，禁止动画 width/height/top/left。
  3. 进出场不对称：进场 decelerate（快进慢停），出场 accelerate（慢起快出），出场更短。
  4. 尊重 reduced-motion：全局降级，非可选项。
  5. 毛玻璃场景减少位移：模糊层 + 位移同时动画会掉帧，glass 下位移距离减半。

子集化脚本：扫描源码里所有 集合:图标名，只打包实际用到的图标（绝不能全量打包 mdi 的 7000+ 图标）。

javascript
/**
 * 扫描源码中所有 `集合:图标名` 形式的图标引用
 * @param {string} dir 扫描根目录
 * @returns {Set<string>} 去重后的图标全名集合
 */
function scanIconUsage(dir) {
  const found = new Set()
  const walk = (p) => {
    for (const entry of readdirSync(p)) {
      const full = join(p, entry)
      if (statSync(full).isDirectory()) { walk(full); continue }
      if (!/\.(vue|ts|tsx|md)$/.test(entry)) continue
      const code = readFileSync(full, 'utf-8')
      for (const m of code.matchAll(/['"`]([a-z0-9-]+:[a-z0-9-]+)['"`]/g)) found.add(m[1])
    }
  }
  walk(dir)
  return found
}

三条兜底：① 在线时未命中离线数据则回退 Iconify API；② 渲染失败走 fallback 插槽显示占位框；③ CI 里 check-icons.mjs 校验源码中所有图标都在离线集合内，缺一个即报错。

8.3 按需引入与 Tree-shaking 的关系

关注点结论
SrIcon 的 name 是字符串无法被 tree-shaking 分析，图标体积必须靠显式子集控制
组件代码本身ESM + sideEffects: false（除样式），未用组件可被摇掉
图标集合 JSON以 @sunset-reverie/icons/offline 子路径导出，不用时不进产物
@iconify/vue 运行时约 15KB gzip，无法去掉（去掉需方案 2，不推荐）
sideEffects: false 的前提：offline/index.ts 不能有顶层副作用（不写 addCollection() 调用），注册动作由 SrIcon 运行期执行。否则改为精确声明 "sideEffects": ["./dist/offline/index.js"]。

09组件设计规范

统一的 props / slots / emits / 透传 / A11y 约定，让 30 个组件像同一个组件。

9.1 通用 Props

Prop类型默认说明
size'xs' \| 'sm' \| 'md' \| 'lg' 或响应式对象'md'尺寸阶梯，与 Token 对齐

disabledbooleanfalse必须同时设置 aria-disabled
loadingbooleanfalse禁用交互但保留 DOM
blockbooleanfalse占满父容器宽度

硬性约定

  • props 定义抽到独立 .ts，as const + ExtractPropTypes，禁止在 .vue 内联对象字面量（类型无法外部复用）。
  • 布尔 prop 默认值必须为 false：<sr-button disabled> 的直觉是「禁用」。
  • 枚举用联合类型 + as const，不用 TS enum（有运行时对象，对 tree-shaking 不友好）。
  • 所有 props 必须有 JSDoc，注释会被 vue-component-meta 提取到文档站。
  • 禁止与 DOM 原生属性冲突：SrButton 的 type 改名为 htmlType。

9.2 Slots 规范

插槽名约定

9.3 Emits 规范

  • v-model 统一 modelValue + update:modelValue；多绑定用 v-model:visible。
  • 事件名 kebab-case，动词开头：change / open / confirm / select。
  • payload 必须是对象（超过 1 个参数时），便于扩展。
  • 需要阻断的场景（before-close）用回调式而非事件式。
typescript
// ✅ 推荐：payload 是对象，后续加字段不破坏兼容
emit('change', { value, previousValue, source: 'user' })

// ❌ 不推荐：加参数即破坏性变更
emit('change', value, previousValue)

// 显式类型声明
const emit = defineEmits<{
  'update:modelValue': [value: string]
  change: [payload: { value: string; previousValue: string }]
  clear: []
}>()

11.3 样式产物策略（tree-shaking 关键）

方案做法优点缺点结论
A. 单一全量 CSS只产出 style.css简单按需引入失效❌
B. base + 每组件独立base.css + components/x/style.css真正按需下游需引 base✅ 采用
C. 每组件自包含 base组件 CSS 内 @import base引一个就够base 重复 N 次❌
D. CSS-in-JS 注入组件内 import './style.less'零配置SSR 首屏无样式闪烁❌

采用 B，并由工具自动补齐：resolver 的 sideEffects 先返回 base 再返回组件样式；Nuxt Module 把 base.css 注入 css 数组。下游全量引入只写两行：

typescript
import '@sunset-reverie/ui/base.css'    // reset + token + 动画 + 工具类（全局唯一）
import '@sunset-reverie/ui/style.css'   // 全部组件样式
为什么 base.css 必须独立：CSS 变量的 :root 块若被打进每个组件 CSS，会①体积重复；②后加载的组件可能覆盖前面的主题变量（同优先级后写胜出），造成「主题切换在某个页面莫名失效」。

/**
 * SunsetReverie-UI 的 Nuxt 模块
 * 职责：注册组件、注入样式与插件、注入 SSR 主题脚本
 */
export default defineNuxtModule<ModuleOptions>({
  meta: {
    name: '@sunset-reverie/nuxt',
    configKey: 'sunsetReverie',
    compatibility: { nuxt: '^4.0.0' },
  },
  defaults: {
    prefix: 'Sr', injectBaseStyle: true, injectThemeScript: true,
    injectSsrBreakpoint: false, defaultTheme: 'light', defaultStyle: 'flat',
    components: true, iconifyOffline: true,
  },
  async setup(options, nuxt) {
    const { resolve } = createResolver(import.meta.url)

    // 1. 全局基础样式必须最前，保证 CSS 变量先于组件样式生效
    if (options.injectBaseStyle) {
      const css = nuxt.options.css as string[]
      if (!css.includes('@sunset-reverie/ui/base.css')) {
        css.unshift('@sunset-reverie/ui/base.css')
      }
    }

    // 2. 注册组件：借 addComponent 让 Nuxt 按需打包（SSR 友好）
    for (const name of COMPONENTS) {
      addComponent({
        name: `${options.prefix}${name}`,
        export: `${options.prefix}${name}`,
        filePath: '@sunset-reverie/ui',
        priority: 1,
      })
    }

    // 3. 组合式函数自动 import
    addImportsDir(resolve('./runtime/composables'))

    // 4. 主题插件（enforce: 'pre'，在首屏渲染前注入脚本）
    if (options.injectThemeScript) {
      addPlugin({ src: resolve('./runtime/plugin'), mode: 'universal' })
    }

    // 5. 用户配置注入 runtimeConfig
    nuxt.options.runtimeConfig.public.sunsetReverie = {
      defaultTheme: options.defaultTheme!,
      defaultStyle: options.defaultStyle!,
      iconifyOffline: options.iconifyOffline!,
    }
  },
})
Nuxt 侧只用 addComponent，不再叠 unplugin-vue-components。 Nuxt 的组件注册本身就是按需打包的；叠一层 resolver 可能出现「同名组件注册两次」的告警。

C. reset 要点

less
/* 用 :where() 包裹，特异性为 0：业务样式可无成本覆盖 */
:where(*, *::before, *::after) { box-sizing: border-box; }

:where(html) {
  font-family: var(--sr-font-family-base);
  font-size: var(--sr-font-size-base);
  line-height: var(--sr-line-height-base);
  color: var(--sr-color-text);
  background: var(--sr-color-bg-page);
}

:where(body) {
  margin: 0;
  min-height: 100dvh;
  // 毛玻璃需要页面有背景，否则模糊出来的是一片灰
  background: var(--sr-color-bg-page);
}

:where(h1, h2, h3, h4, h5, h6, p, figure, blockquote, dl, dd) { margin: 0; }
:where(ul, ol) { margin: 0; padding: 0; list-style: none; }
:where(button, input, select, textarea) { font: inherit; color: inherit; }
:where(img, svg, video) { display: block; max-width: 100%; }
base.css 是全局注入的，reset 若用裸 * 选择器（特异性 0,0,1）会与业务样式频繁冲突。用 :where() 把特异性归零，业务侧任何选择器都能覆盖 —— 这是「组件库 reset 不污染业务」的关键技巧。
